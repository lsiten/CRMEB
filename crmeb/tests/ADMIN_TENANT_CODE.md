# 后台登录可选租户编码契约（LSIT-21）

实施基准：PR #45，723cf5b24cf269ec4f34738b7f44a0960fc435ee。

- `POST /adminapi/login` 新增可选字符串 `tenant_code`，最长 64 字符，去除首尾空白；省略、空串和纯空白保持原有“全局唯一未删除账号”路径。显式 null、数组和其他非字符串拒绝，业务 400“租户编码格式错误”。
- 非空 code 按数据库既有排序规则匹配租户 code，仅恰好一个匹配且启用时继续；只查询其 tenant_id 下未删除的 account。错误/停用/歧义 code、租户内账号不存在或重名、密码错误统一 HTTP 200 + 业务 400“账号或密码错误”，沿用 login_captcha 字段，不回落、不按密码猜租户。账号禁用继续沿用 400“您已被禁止登录”。
- tenant_code 是公开定位信息，不是认证凭据。验证码、account/pwd、成功响应与后续 Bearer 认证保持原样；保存登录记录与签发令牌均使用账号原归属。无分页、金额或 C 端接口变化。
- 后台交接：登录页增加可选“租户编码”文本输入，提示“同名账号请填写所属租户编码”；留空可省略字段，填写后与 account/pwd 同次提交，不重试其他租户、不自动选首项、不要求改名。后台代码由知衡另行交明镜实施，本次不修改。
- 唯一性依据：`public/install/tenant_migration.sql:8` 的 code 唯一索引；`app/adminapi/controller/v1/setting/Tenant.php` create/update 均有 code 重名检查。查询仍限制两条并拒绝歧义，防御现有环境 schema 漂移；未检查或迁移现有数据库。

本契约替代 ADMIN_LOGIN.md 中“跨租户同名账号需消除歧义后才能登录”的限制；未传编码时仍拒绝跨租户同名。
