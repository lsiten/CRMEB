## CRMEB Taro 页面装修能力补齐与复刻 PRD

版本：V2.0（Taro 主线）  
适用源码基线：`template/taro-miniapp` 当前工作树；后端协议基线为 CRMEB 默认分支（审查提交 `05987cced`）  
需求来源：`diy-platform-replication.md`、营销组件 UI 图集、现有 CRMEB 接口与 Taro 源码

## 1. 结论与产品决策

### 1.1 结论

本项目以现有 `template/taro-miniapp` 为唯一 C 端实施主线，采用 React + TypeScript + Taro 4.x，首期默认编译微信小程序。后台编辑器和 ThinkPHP 持久化能力继续复用；页面装修 JSON、商品/营销业务接口作为跨端协议，运行时组件需在 Taro 中重新实现。

现阶段可行，但不是“直接替换渲染层”：Taro 目录只有可运行骨架，尚无 DIY JSON 解析器、组件注册表、鉴权、缓存、装修页面路由和营销组件。应先建立协议闭环，再逐批迁移组件。参考实现和历史数据仅用于核对协议、字段及行为，不构成另一端的开发目标。

### 1.2 版本范围

- **本期交付**：Taro 首页装修 MVP（协议解析、基础组件、商品数据、登录/错误降级）及可验证的组件迁移基础设施。
- **后续迭代**：营销、会员、个人中心、商品详情和多端适配，按里程碑逐步扩大白名单。
- **发布原则**：未进入 Taro 白名单的组件不得出现在 Taro 可发布页面；历史模板遇到未支持组件时显示占位，不得白屏。

## 2. 当前基线（Baseline）

### 2.1 工程与构建

- 目录：`template/taro-miniapp`。
- 技术栈：Taro 4.2.x（package 声明 4.1 兼容范围）、React 18、TypeScript 5.6、Webpack 5；脚本为 `dev:weapp`、`build:weapp`、`typecheck`。
- 页面注册：`src/app.config.ts` 已注册首页、商品、购物车、个人中心及 tabBar。
- 样式：各页面独立 SCSS，尚未形成装修组件的公共设计 token。

### 2.2 已有功能

- 首页存在静态轮播/快捷入口/推荐位骨架。
- 商品页可展示简化商品模型并加入本地购物车。
- 购物车使用 Taro Storage 保存数量，结算入口提示登录。
- 个人中心提供登录入口及订单/地址/优惠券/客服菜单骨架。
- `src/services/api.ts` 已封装 Taro 请求类型，但 `baseUrl` 当前为固定 `http://localhost/api`，尚未接入 CRMEB 鉴权、错误码和环境配置。

### 2.3 后端与协议可复用项

- 管理端 DIY CRUD、模板启用/恢复、页面背景及版本字段可继续作为数据源。
- 页面载荷沿用 `id/name/title/type/status/is_show/version/value` 等字段；`value` 兼容专业数组与旧对象格式。
- 商品、文章、秒杀、拼团、砍价、预售、积分、优惠券、直播、用户等接口作为 Taro services 的后端依赖。

## 3. 差距与优先级

| 能力 | 当前基线 | 目标与优先级 |
|---|---|---|
| API 环境与鉴权 | localhost 固定地址，无 token 注入/统一错误 | P0：环境变量、请求拦截、401/超时/重试策略 |
| DIY 读取 | 无页面读取与 JSON 归一化 | P0：数组/旧对象兼容、排序、隐藏、schema 校验 |
| 组件分发 | 无注册表、无动态渲染器 | P0：`name` 注册表、未知组件占位、单组件隔离 |
| 基础组件 | 仅静态首页骨架 | P0：轮播、图文、导航、商品列表、富文本安全子集 |
| 页面路由 | 仅固定四页 | P0：装修首页/专题页路由，内部链接白名单 |
| 登录与业务态 | 仅提示登录 | P1：登录态 store、业务接口错误/空态、实时价格库存 |
| 营销组件 | 未实现 | P1：按活动状态迁移 12 类组件，逐项验收 |
| 详情/个人中心装修 | 固定骨架 | P1/P2：复用同一协议，增加页面类型适配 |
| 视觉与监控 | 无基线 | P2：截图回归、埋点、慢请求与崩溃监控 |

## 4. 目标与非目标

### 4.1 本期目标

1. Taro 能从 `v2/diy/get_diy/:name` 读取启用页面并安全归一化。
2. 通过显式注册表渲染 P0 基础组件；单组件异常不阻断整页。
3. 商品列表只持久化 ID，运行时读取实时价格、库存和上下架状态。
4. 支持保存后的刷新、隐藏、排序、背景和未知字段透传验证。
5. 建立微信小程序构建、类型检查、单元测试和真机冒烟门槛。

### 4.2 非目标

- 不新增后台编辑器，不重做 ThinkPHP 业务域和数据库模型。
- 不把历史参考实现作为继续开发或发布目标；仅用于字段、交互和接口核对。
- 不在首期承诺全部营销组件、商品详情、个人中心或像素级视觉复刻。
- 不开放任意 HTML/JavaScript 注入；富文本、链接和自定义元素均采用白名单。

## 5. 功能需求

### P0：协议与运行时闭环

**FR-01 页面读取与归一化**

- 请求页面、版本和主题接口；响应不是合法 JSON 时进入安全默认页并记录可追踪错误。
- 输入支持数组和旧对象两种 `value`；未知字段透传，缺失字段使用组件默认值。
- 过滤 `isHide=true`；有 `timestamp` 时按数值升序，无值时保持原顺序。
- 页面级背景、标题、版本和 `schema_version` 保留；迁移失败不得覆盖原始载荷。

**FR-02 Taro 组件注册表**

- 以 `name/defaultName` 作为唯一类型标识，注册项包含：组件版本、默认配置、渲染器、适用页面、链接能力、降级策略。
- P0 白名单：`swiperBg`、`headerSerch`、`tabNav`、图文/富文本安全子集、`goodList`/`goodRecommend`、`member`（静态入口）。
- 暂不支持项在 Taro 页面显示“暂不支持当前版本”占位；禁止静默丢弃，允许用户返回后台处理。

**FR-03 数据与操作安全**

- 请求层从环境配置读取 API 地址，统一注入登录凭证，处理 401、超时、业务错误和重试。
- 内部跳转仅允许已注册页面和业务类型；外链仅允许配置白名单的 HTTPS 地址。
- 富文本仅允许安全标签、样式和图片域名；禁止脚本、事件属性和危险 scheme。

**FR-04 列表数据与状态**

- 装修配置只保存商品/文章/活动 ID 及展示参数，不保存完整对象。
- 商品列表数量遵守后端 `limitMax`（默认 50）；Taro 端再次校验并对超限做可见错误提示。
- 价格、库存、活动状态以服务端响应为准；组件请求失败只影响自身并提供重试/空态。

### P1：营销与用户组件

按相同闭环迁移 `activeParty`、`seckill`、`bargain`、`combination`、`presale`、`pointsMall`、`coupon`、`signIn`、`liveBroadcast`、`customComponent`、`member`、`userInfor`。每个组件须通过正常、无数据、未登录、接口失败和不支持终端五类场景。

- 活动价格、库存和资格不可由装修配置覆盖。
- 领取优惠券、签到、会员和用户信息在未登录时进入统一登录流程。
- `liveBroadcast` 首先限定微信小程序；其他编译目标显示明确降级。
- `customComponent` 仅实现 Picture、Text、Icon、Line、Panel 及白名单字段绑定，不执行任意代码。

### P2：治理与体验

- 未保存变更提示、加载骨架、重复请求保护、组件级错误边界。
- schema 版本、迁移器、导入导出校验和操作日志。
- 组件截图回归、关键点击埋点、慢请求和错误监控。

## 6. 数据与接口契约

页面级字段保留 CRMEB `eb_diy` 语义：`id/name/title/type/status/is_show/version/is_bg_color/color_picker/is_bg_pic/bg_pic/bg_tab_val/order_status/value`；导入导出新增 `schema_version`，缺省为 `1`。

Taro service 至少提供：

- `getDiyPage(name)`、`getDiyVersion(name)`、`getTheme(name)`；
- `getGoodsList/queryGoods(ids)` 及营销数据查询；
- `request` 统一处理 base URL、token、业务错误和取消请求。

后端接口继续复用 `v2/diy/get_diy/:name`、`v2/diy/get_version/:name`、`v2/diy/color_change/:name`、`v2/diy/sign` 及现有商品/营销接口。管理端保存校验仍由 `diy/save/:id`、`diy/diy_save/:id` 负责；Taro 端不绕过管理端写库。

## 7. 验收标准

- **AC-01 构建**：`pnpm typecheck` 与 `pnpm build:weapp` 通过，产物可在微信开发者工具启动。
- **AC-02 协议兼容**：数组、旧对象、未知字段、损坏 JSON fixture 均有测试；损坏数据不白屏。
- **AC-03 页面闭环**：首页读取启用模板，轮播/导航/商品列表渲染；刷新后顺序、隐藏和背景一致。
- **AC-04 数据正确性**：超限商品列表被拒绝；页面不保存完整商品对象；下架商品不可展示可购买状态。
- **AC-05 安全**：未登录、401、超时、业务失败、危险链接和富文本注入均有可见且可恢复的处理。
- **AC-06 组件隔离**：未知或渲染异常组件只显示占位，其他组件继续工作，并输出组件名/实例标识日志。
- **AC-07 回归证据**：微信小程序真机完成首页、商品、购物车、个人中心冒烟；P1 组件逐项附正常/空态/失败证据。

## 10. 风险、监控与回退方案

| 风险 | 影响/预警 | 缓解与回退 |
|---|---|---|
| Taro 与历史组件模型不一致 | 组件错误率、未知组件占比上升 | 白名单分批发布；未知组件占位；按 `schema_version` 回退解析器 |
| 后端接口或鉴权不稳定 | 401/5xx、超时率超阈值 | 保留安全默认页和最近成功快照；恢复服务后重试，不写坏缓存 |
| 价格/库存时效性问题 | 下单校验失败、下架商品仍展示 | 只展示服务端实时状态；缓存设短 TTL；下单前再次校验 |
| 首批迁移范围过大 | 里程碑延期、构建包体超限 | 以 M2 为可发布切点，P1 组件逐包/逐页面开启 |
| 视觉差异或真机兼容 | 截图 diff、机型冒烟失败 | 以行为和设计 token 为首要验收；按机型关闭问题组件 |
| 新版本回归 | 监控错误率超过发布阈值 | 灰度开关 `TARO_DIY_ENABLED`：关闭时回到固定首页骨架；保留上一版构建产物和页面快照，支持一键切回 |

**发布回退顺序**：关闭 Taro DIY 功能开关 → 切换到最近稳定页面快照/固定骨架 → 保留原始 JSON 与错误样本 → 修复后仅对受影响组件重新灰度。任何迁移器只有在新载荷校验成功后才允许覆盖，失败自动保留旧版本。
