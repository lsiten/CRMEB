## 适用范围

本文是 CRMEB 发布前的运维交接基线，覆盖后端 `crmeb/`、管理端 `template/admin/` 和移动端 `template/uni-app/`（微信小程序、H5、App）。文档只描述检查、构建和回滚方法，不执行实际发布。所有命令均应在目标环境的变更窗口内由具备权限的发布人执行。

## 一、环境分层与配置来源

| 环境 | 后端 | 管理端 | 移动端 | 数据与外部服务 |
| --- | --- | --- | --- | --- |
| 开发（dev） | `crmeb/.env`，`APP_DEBUG=true` 仅限本地 | `template/admin/.env.dev` | UniApp `config/app.js` 的 `HTTP_REQUEST_URL` 指向开发 API | 独立数据库、Redis、微信测试 AppID/沙箱支付 |
| 预发布（staging） | 由部署平台注入 staging 配置，禁止复用生产密钥 | 构建时注入 staging `VUE_APP_API_URL` | HBuilderX/CI 使用 staging API 和测试 AppID | 生产拓扑的隔离副本，使用脱敏数据 |
| 生产（prod） | 服务器或 Secret Manager 注入；`APP_DEBUG=false` | `template/admin/.env.production`，`VUE_APP_API_URL` 必须为 HTTPS | 发行前切换生产 API；生产 AppID/签名仅由发布人使用 | 生产数据库、Redis、对象存储、支付/短信/物流正式账号 |

配置优先级固定为：Secret Manager（或 CI 受保护变量）> 运行时环境变量 > 未提交的本地 `.env`；如需新增模板，请使用明显的占位符（当前仓库以安装文档中的配置示例为准）。不要把生产配置复制回开发目录。

### 后端变量清单

以 `crmeb/.env` 和 `help/dev-docs/phpapi/系统安装流程文档.md` 的分组为准，至少核对：

- `[APP]`：`APP_KEY`、`DEFAULT_TIMEZONE`、`APP_DEBUG`。
- `[DATABASE]`：`TYPE`、`HOSTNAME`、`HOSTPORT`、`USERNAME`、`PASSWORD`、`DATABASE`、`PREFIX`、`CHARSET`、`DEBUG`。
- `[REDIS]`：`REDIS_HOSTNAME`、`PORT`、`REDIS_PASSWORD`、`SELECT`；启用队列时同时核对 `[QUEUE] QUEUE_NAME`。
- `config/*` 中通过 `env(...)` 读取的第三方配置：微信/支付宝支付、短信、七牛或其他对象存储、物流查询、OAuth 等。按实际启用的服务逐项登记，不使用的服务保持关闭。

生产禁止使用仓库示例中的弱默认值（例如 `APP_KEY=crmeb`）、空数据库/Redis 密码或 `APP_DEBUG=true`。密钥轮换时先在 Secret Manager 建立新版本，验证新版本可用后再撤销旧版本，并记录操作者与时间。

### 前端变量清单

- 管理端：`template/admin/.env.dev`、`template/admin/.env.production` 的 `NODE_ENV`、`VUE_APP_ENV`、`VUE_APP_TITLE`、`VUE_APP_API_URL`。构建产物中只允许出现公开的 API 地址和展示信息，不得注入支付私钥、数据库密码或其他服务端 Secret。
- UniApp：`template/uni-app/config/app.js` 的 `HTTP_REQUEST_URL`。微信小程序还需核对 `manifest.json` 的 AppID、合法域名、业务域名和上传者权限；H5 需核对 HTTPS、CORS 和 CDN；App 需核对包名、Bundle ID 和签名文件。

## 二、密钥注入与“不入库”约束

1. 在 CI/CD 或云主机 Secret Manager 中创建按环境隔离的变量组（`staging`、`prod`），生产变量禁止在普通日志、构建缓存和制品中回显。
2. 部署前由发布脚本将变量注入进程环境或受限权限的运行时文件（建议 `0600`、属主为应用用户）；禁止把密钥放在命令行参数、构建参数或可被 shell 历史记录的命令中。运行时文件使用完立即安全删除并验证不存在；限制应用用户和诊断账户的 `/proc/<pid>/environ`、进程列表及调试接口可见性，禁止无批准的 `ptrace`。生产主机默认禁用 core dump（或使用不含密钥的受控转储目录），崩溃报告、诊断包和子进程环境继承均须脱敏。发布完成后清理临时文件；shell 历史仅按安全事件/审计策略处理，不得为掩盖操作而擅自删除审计记录。
3. 私钥、证书、API Key、数据库/Redis 密码、JWT 密钥、`APP_KEY` 不得提交 Git、写入 Docker 镜像层、前端源码或 issue/日志。证书文件只挂载到运行时只读路径。
4. 提交前执行 `git diff --check`，并用 Secret 扫描器检查提交、制品和日志；发现泄露立即吊销/轮换，不能只删除文本后继续使用原密钥。
5. `.env` 仅作本地文件；新增变量先补充安装文档或专用示例（占位符），再在 Secret Manager 配置真实值。不得把真实生产值填入示例文件。

若历史提交已包含真实凭据，先按泄露事件处理（立即轮换/吊销并保留不可篡改的安全事件审计记录），再通过批准的独立变更清理 Git 历史、构建缓存、镜像层以及可控的 fork/备份副本，并保留脱敏模板；仅修改 `.gitignore` 或删除当前文件不能使历史中的凭据失效。清理范围、批准人、工具、时间和无法回收的外部副本须登记，不能以清理 shell 历史替代审计留存。

## 三、发布前检查清单（勾选后才允许进入窗口）

### 代码、构建与数据

- [ ] 变更已合并到目标发布分支，版本号、数据库迁移和依赖锁文件可追溯；已生成制品校验和并保存构建日志。
- [ ] 后端 `APP_DEBUG=false`，PHP 扩展、Nginx/HTTPS、文件权限和队列进程检查通过；健康检查、登录、下单、支付回调、退款、文件上传各至少验证一次。
- [ ] 已完成数据库全量备份、增量/binlog 保留和恢复演练；备份采用独立密钥加密，写入具备对象锁/不可变保留的隔离账户，仅授权恢复角色可读写，访问按最小权限审批并留存审计。已明确 RPO/RTO、恢复负责人和双人复核，记录迁移前后的 schema 版本。
- [ ] Redis、对象存储、短信、物流和支付回调地址均指向生产；回调白名单、超时、重试和幂等策略已验证。
- [ ] 管理端执行生产构建并检查 API 地址；UniApp 分别在目标端真机验证登录、核心交易、分享/订阅消息和异常网络。

### 小程序审核与隐私合规

- [ ] 微信/支付宝等平台主体、类目、服务资质、隐私保护指引、用户协议、客服入口和备案信息已更新且与实际上线功能一致。
- [ ] 首次启动不强制索取无关权限；定位、相册、摄像头、通讯录等按需申请并说明用途，拒绝权限时核心页面仍有可用替代路径。
- [ ] 收集清单已登记数据项、目的、处理方式、保存期限、共享/委托方和删除渠道；仅收集最小必要数据，敏感信息传输和存储加密，日志脱敏。
- [ ] 第三方 SDK、隐私弹窗、儿童/未成年人规则、注销和数据导出流程已在审核包中实测；平台隐私接口声明与代码调用一致。
- [ ] 审核截图、测试账号、隐私文本和版本说明已归档；测试账号使用合成数据和一次性/最小权限凭据，禁止使用生产账号。材料、联系人、请求日志和故障证据先脱敏（Token、Cookie、密码、用户标识、内部地址等），仅授权审核/安全人员可读，设置保留期限并到期销毁；审核被拒时有责任人与整改时限，不通过审核不切生产流量。

### App 签名预案

- [ ] Android keystore、iOS 证书/Provisioning Profile 的别名、有效期、指纹、用途和负责人已登记；文件存放于密码库/Secret Manager，禁止入库。
- [ ] 发布机仅在受控环境读取签名材料，启用最小权限和双人复核；已提前检查证书在发布窗口内不会过期。
- [ ] 已准备签名轮换方案：旧包仍可升级、备份密钥和恢复联系人可用；证书丢失或泄露时立即吊销并按平台流程重签，必要时发布紧急修复包。
- [ ] 从同一制品生成 Android APK/AAB 和 iOS IPA，记录 SHA-256、版本号、Build Number，并在至少一台真机安装升级验证。

## 四、灰度发布、监控与回滚

### 建议流程

1. **冻结与备份**：记录当前版本、配置版本、迁移版本、关键指标基线；停止高风险 schema 变更，完成备份并确认恢复点。
2. **预发布验证**：用脱敏数据执行冒烟和回归，验证队列积压、支付/物流回调、定时任务和告警链路。
3. **小流量灰度**：先放 1%（或单租户/单地域）流量，观察至少一个业务高峰周期；再按 5% → 25% → 50% → 100% 分级，每级需人工确认。
4. **监控门槛**：持续观察 5xx、接口 P95、登录/下单/支付成功率、队列积压、数据库连接/锁等待、错误日志和客户端崩溃率。任一关键指标较基线恶化 20%，或出现资金/数据一致性问题，立即停止放量并回滚。
5. **完成与归档**：全量后保留旧制品和旧配置至少一个发布周期，更新版本台账、变更记录、监控截图和审批记录。

### 回滚步骤

1. 宣布回滚并冻结新流量，保留故障时间线、请求 ID 和相关日志；不要删除现场。
2. 将路由/实例切回上一稳定制品，恢复上一版本运行时配置；确认健康检查和核心接口恢复。
3. 若涉及数据库迁移，优先执行预先验证过的**向前兼容修复**；只有在明确验证且获批准时才从备份恢复，避免直接回退已写入的新字段/数据。
4. 暂停或重放受影响队列，按幂等键核对订单、支付、库存和退款，禁止人工重复扣款；必要时通知支付/客服负责人。
5. 回滚后观察一个完整监控周期，完成数据一致性抽样、用户影响评估和审计记录；补充根因、修复版本与再次发布条件。

紧急联系人至少包括发布负责人、后端/前端负责人、数据库负责人、支付/小程序平台联系人和安全/合规负责人。每次发布前将联系人、制品地址、备份恢复点和回滚指令填入变更单。

## 五、验收证据与禁止事项

发布单必须附：构建日志与校验和、环境变量版本（仅变量名和版本号）、备份/恢复验证记录（含 RPO/RTO、恢复权限和审计结果）、审核与隐私材料、签名指纹、灰度指标截图、审批人与时间线。所有证据均须脱敏、按最小权限访问并标注保留/销毁日期；到期销毁前完成复核，销毁动作留存审计。禁止在仓库、制品、前端包、issue、聊天或日志中出现真实敏感信息；本文中的示例值均为占位符。
