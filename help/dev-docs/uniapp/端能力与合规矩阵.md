## 目的

本文是 CRMEB 移动端首发（微信小程序）及 H5、App-Plus 后续平台的端能力基线。业务代码调用能力前应先判断平台和能力可用性；不可用时必须走本表的降级路径，不得阻塞浏览、下单或售后等核心流程。

## 平台差异清单与降级策略

## 合规约束

1. 隐私弹窗必须在任何已声明隐私接口（手机号、头像、相册、相机、定位、剪贴板等）首次调用前完成；不得通过预调用接口探测权限。
2. 权限文案写明“用途、是否必要、拒绝后的影响”，并与《隐私政策》中的个人信息清单保持一致。只申请当前操作所需的最小权限。
3. 支付结果以后端订单状态为唯一事实来源。客户端回调只负责刷新状态，禁止把 `requestPayment:ok` 直接写入已支付状态。
4. 分享、深链和剪贴板内容视为不可信输入：限制长度、白名单字段并进行 URL 编码；解析失败丢弃参数并记录可检索的错误码，不记录手机号、token 等敏感值。
5. 所有能力失败回调都要关闭 loading、给出可理解的提示，并保留重试或替代路径；不得静默吞掉关键失败。

## 微信小程序真机冒烟（发布前必做）

- 清理小程序缓存后首次进入登录页：隐私弹窗出现；同意后可登录，拒绝后不调用手机号/头像接口。
- Android 与 iOS 各验证一次：相册选择、相机拍照、取消授权、系统设置重新授权；上传失败可重试。
- 发起微信支付和通联支付：成功、取消、网络中断后返回收银台，`onShow` 均能显示服务端真实订单状态。
- 从普通链接、扫码小程序码、带 `scene` 的分享卡片进入，`spread/spid/agent_id` 只绑定一次且参数异常不崩溃。
- 复制订单号、物流号：成功时提示“已复制”；系统禁用剪贴板时仍显示可长按复制文本。
- 发布有新版本和下载失败两种场景：成功可确认重启，失败可继续使用并可稍后重试。
- 分享到好友和朋友圈（若平台开放）：标题、封面、业务 ID 正确；H5/App 不支持时出现复制链接兜底。
